Decisiones y Riesgos Técnicos del Alcance Ampliado
Nuevos Riesgos (KDS & Disponibilidad)
Mitigaciones Arquitecturales
🖨️ Impresión de comandas térmica (ESC/POS 58/80 mm)
Dependencia de hardware externo. Mitigación: cola de impresión con reintento manual desde el KDS; el pedido nunca se bloquea si la impresora no responde.
🍳 Estados por ítem de pedido
Cambio de esquema (estado por línea de pedido) + canal SSE dedicado de cocina. Se aplica con migración incremental sin romper el dashboard de mozo ni el flujo actual del comensal.
🕑 Resolución de la carta del comensal
Disponibilidad + franja horaria + estado de apertura se resuelven en una sola consulta indexada para no penalizar el tiempo de carga de la carta.
Riesgo de Cadencia Semanal
Control de Ejecución
⏱️ Menor margen por sprint
Cada épica se acota a 2–4 US ejecutables en una semana. Si una US no cierra, se corta el alcance (no la calidad) y se reprograma; la fecha del 08/11 no se mueve.
🔁 Overhead de ceremonias
Planning y review se comprimen a revisiones cortas de inicio/cierre de semana. El release semanal a Render funciona como demo continua para feedback docente.
✅ Calidad
Se mantiene la regla de merge: go test ./... + npm run build verdes antes de integrar a qa y luego a main.
